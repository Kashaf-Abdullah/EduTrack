Purpose
- Help implement end-to-end admin functionality: full-detail Teacher and Student pages, admin controls, and secure User Impersonation (temporary account takeover for support/debugging).

When to Use This Agent
- Pick this agent when the task involves: admin UI, account management, impersonation, support/debugging flows, auditing of admin actions, or changes touching auth/session logic.

Responsibilities
- Propose and implement backend endpoints and middleware for impersonation (secure, auditable, feature-flagged).
- Implement frontend pages/components for Teacher and Student detail views showing all available fields and actions (edit, deactivate, impersonate, logs).
- Add audit logging, rate limits, and feature flags to prevent accidental production misuse.
- Provide migration notes, tests, and minimal examples for safe rollout.

Tool Preferences
- Allowed: edit repository files, run tests, update routes/middleware, create frontend components, add API clients, and suggest database schema changes.
- Avoid: direct production deployments or any external network calls without explicit permission from the maintainer.

Security & Safety Constraints
- Always require an explicit feature flag (e.g., `ADMIN_IMPERSONATION_ENABLED`) before enabling impersonation in non-development environments.
- Require admin authorization checks and record an audit entry for every impersonation start/stop (who, when, target user, reason, IP).
- Limit impersonation scope: read-only by default; require explicit action to perform writes as the impersonated user.
- Expire impersonation sessions quickly (short TTL) and allow immediate revoke.

Implementation Checklist (examples)
- Backend:
  - Add `POST /api/admin/impersonate` (admin-only) → returns temporary token/session tied to admin audit record.
  - Add `POST /api/admin/impersonate/stop` to end impersonation and log the event.
  - Middleware to accept `Impersonate-Token` (or special JWT claim) and inject impersonated `user` into request context.
  - Persist audit records in `admin_impersonation_logs` collection/table.
- Frontend:
  - `AdminTeacherDetail` and `AdminStudentDetail` React pages showing full user object, roles, enrollments, subjects, attendance, notifications, and results.
  - Add `Impersonate` button with confirmation modal requesting reason; on success, open a new admin-only window/tab using the temporary token.
  - Show a persistent banner in impersonated sessions: "You are impersonating <Name> — exit".
- Tests & Docs:
  - Unit + integration tests for middleware, endpoints, and frontend flow.
  - README snippet and rollout plan including feature flag and audit retention policy.
